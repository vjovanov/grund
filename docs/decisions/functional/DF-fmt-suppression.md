# DF-fmt-suppression: fmt suppression is per file and per region, and the index carve-out outranks both

**Status:** Accepted
**Date:** 2026-09-03

## 1. Context

A citation's *position* sometimes carries meaning. An ASCII topology diagram whose edge labels are citations is navigable — `grund refs` finds them, the LSP hovers them, `grund check` counts them as edges — and it is navigable only because it is **not** a fenced code block, where citations are deliberately dead ([§FS-fmt.6.4](../../functional-spec/FS-fmt.md#64-what-is-never-wrapped)). Inside an HTML `<pre>` block or a four-space indented block the citations are live and the alignment is the document.

`grund fmt --write` then wraps each one into `[§ID](path#anchor)`, which destroys the alignment and, in an HTML block, renders as raw link markup. The only opt-out was project-wide, `[fmt.cross_refs] enabled = false` ([§FS-fmt.6.7](../../functional-spec/FS-fmt.md#67-configurability)), and the never-rewrite list of [§FS-fmt.2.3](../../functional-spec/FS-fmt.md#23-what-is-never-rewritten) is fixed: fences, inline code spans, declaration headings, dangling citations. So a repository with one diagram had three options — backtick every citation in it and accept literal backticks in the rendered `<pre>`, turn generated links off everywhere, or let the diagram be reformatted. This project took the second, which made cross-reference links an adoption blocker for its own tree.

## 2. Decision

Two suppression scopes, specified together in [§FS-fmt.2.5](../../functional-spec/FS-fmt.md#25-suppressed-scopes). Both stop **every** rewrite `fmt` performs and change nothing else: the file is still walked, the citations still resolve, dangle, and count, and `check`, `refs`, `show`, and `cover` say exactly what they said before.

### 2.1 One general `[fmt] exclude`, not one exclude per pass

The per-file scope is a single `exclude` list under a new `[fmt]` table ([§FS-config.3.10](../../functional-spec/FS-config.md#310-fmt--suppressing-the-rewrite)) covering all four rewrites — trigger-to-marker, bare-to-marker, shorthand-to-canonical, and cross-reference wrapping — rather than a `[fmt.cross_refs] exclude` that only stops the pass this was reported against.

Every rewrite disturbs a protected diagram. A `$$` that becomes `§` shifts a column; an expanded shorthand writes a whole slug into the line; the wrap is merely the loudest of the four. A reader who has said "do not edit this file" has said it about the file, and one key that means that is easier to state, to check, and to remember than four keys that each mean a quarter of it. The narrower form is still reachable if a later case demands it — a `[fmt.cross_refs] exclude` would be additive beside this one — but shipping four knobs to serve a request none of them was made about is how a config surface stops being learnable ([§GOAL-friendliness-first](../../goals.md#goal-friendliness-first-as-user--and-agent-friendly-as-possible)).

The table is `[fmt]`, not a key under `[fmt.cross_refs]`, because the setting is about the command and not about cross-references. That also leaves `[fmt.cross_refs]` exactly what [§FS-fmt.6.7](../../functional-spec/FS-fmt.md#67-configurability) says it is: the home of cross-reference settings.

### 2.2 An in-text region, not a rule keyed by declaration section

The per-region scope is a comment directive pair — `grund:fmt off` … `grund:fmt on` — written in the file, rather than a config rule keyed by a declaration's section path (`AR-topology.2` → do not wrap).

A directive sits beside the thing it protects. It moves with the diagram when the diagram moves, it survives a renumbering of the sections around it, and it is visible to the person editing the lines it governs — which is the person who will otherwise wonder why their citation did not get wrapped. A section-keyed rule is invisible from the file it governs and detaches silently the first time a section is inserted above it: the config still names a real coordinate, the coordinate now names a different region, and the failure surfaces as a diagram quietly reformatted on someone else's commit.

The section-keyed form is also the wrong unit twice over. A protected diagram is rarely a whole numbered section, so the rule over-reaches; and a file can carry a protected diagram and ordinary prose that *should* be wrapped, which the region form handles by construction and the coordinate form handles by adding more coordinates.

Directive text is fixed rather than configured, for the reason [§FS-config.6](../../functional-spec/FS-config.md#6-what-is-not-configured-here) keeps other things fixed: a suppression marker that reads differently per repository is one an agent cannot recognize on sight.

### 2.3 The index carve-out outranks both

[§DF-index-always-linkified](DF-index-always-linkified.md#df-index-always-linkified-the-cross-reference-pass-always-runs-on-a-kinds-index-file) makes a kind's index entries wrapped in every configuration, which is what lets [§FS-check.3.17](../../functional-spec/FS-check.md#317-index-entry-is-not-a-link) demand a link and name `grund fmt --write` as the fix. That carve-out outranks both scopes here ([§FS-fmt.2.5.3](../../functional-spec/FS-fmt.md#253-a-kinds-index-is-still-linkified)), exactly as it already outranks `[fmt.cross_refs] enabled = false`.

Without this, excluding an index file — or opening a region in one — would produce a state `check` reports and the named fix refuses to repair, which is the precise hole [§DF-index-always-linkified](DF-index-always-linkified.md#df-index-always-linkified-the-cross-reference-pass-always-runs-on-a-kinds-index-file) was written to close. The carve-out stays scoped to the entries, so everything else in a suppressed index file is suppressed like anywhere else.

### 2.4 `check` is unchanged, and the repository pays for that

The never-rewrite zones of [§FS-fmt.2.3](../../functional-spec/FS-fmt.md#23-what-is-never-rewritten) are intrinsic: `fmt` may not touch a string literal, so [§FS-check.3.13](../../functional-spec/FS-check.md#313-number-only-shorthand-citation) withholds its shorthand error there rather than demanding an edit the tool refuses to make. It would have been consistent-looking to extend that withholding to a suppressed scope.

It is the wrong reading. Those zones are facts about the text; a suppressed scope is a request by the repository, made in its own config or its own file. Suppressing the finding along with the rewrite would make `grund:fmt off` a region where citations quietly stop being checked — an opt-out from validation wearing the name of an opt-out from formatting — and a reader could no longer say what a green `check` covers without reading every file for directives.

So the cost is stated instead of hidden: a number-only shorthand inside a suppressed scope stays a `check` error that `grund fmt --write` no longer clears, and the author writes the canonical ID or lifts the suppression around that line. The scopes exist to protect hand-aligned text, and hand-aligned text is exactly where an author is already writing the exact bytes they want.

## 3. Alternatives considered

**A `[fmt.cross_refs] exclude` list only.** It answers the reported symptom and leaves three rewrites able to disturb the same diagram, so the next report is the same report about `$$`.

**Widen the fixed never-rewrite list of [§FS-fmt.2.3](../../functional-spec/FS-fmt.md#23-what-is-never-rewritten) to cover `<pre>` and indented blocks.** This is the tempting one: it needs no config and no directive. It fails because it decides for every repository that a citation in an indented block is decorative. Four-space indentation is also list-continuation markup, `<pre>` wraps plenty of ordinary prose, and a repository that wants those wrapped would have no way to say so. The scopes here let the repository decide, which is what [§GOAL-configurable](../../goals.md#goal-configurable-every-default-is-overridable) asks for; making it a fixed rule would put two correctly-configured installs on the same side of a choice neither of them made ([§FS-non-goals.13](../../functional-spec/FS-non-goals.md#13-anything-that-would-let-two-grund-installs-disagree)).

**Let the region directive suppress only the cross-reference pass.** It reads as the minimal change and is the harder rule to explain: a region that stops one of four rewrites needs the reader to know which four there are and which one this is. All-or-nothing matches what the person writing `grund:fmt off` above a diagram means.

**A `.grundfmtignore` file.** A second file to discover, with its own precedence questions, for a list that fits on one line of a config the project already loads.
