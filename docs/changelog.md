# Changelog

Records every notable change to `grund`. Versions follow semver; the **latest release is inline** in this file, and **older releases live one-per-file under `docs/changelog/`** so a reader (human or agent) only loads the history they ask for. Each entry cites the FS/AR/G/DF IDs it touches, so the changelog is itself part of the conformant tree (`grund .` validates the citations).

Schema-version bumps are called out explicitly: `grund_config_version` ([§FS-config.5](functional-spec/FS-config.md#5-schema-versioning)) and the `AGENTS.md` init block version ([§FS-init.2](functional-spec/FS-init.md#2-outputs)). A bump to either is a breaking change for the consumer and must appear under **Changed** with a migration note.

## 1. Conventions

### 1.1 Sections per release

`Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security` — the Keep-a-Changelog set; omit any with no entries. A large entry (the first release, folding in pre-history, is the case in point) may add narrative subsection headings — e.g. `Baseline`, `Renamed`, `Implemented`, `Distribution and bindings` — for readability when the standard six would bury the structure; the semver-relevant changes still live under the standard names.

### 1.2 Schema version callouts

Any change to `grund_config_version` or the `AGENTS.md` block version goes under **Changed** with the prefix `**Schema:**` and a one-line migration pointer.

### 1.3 Entry style

One bullet per change, present tense, leading with the affected ID. Example: `§FS-show: add --head mode for truncated output`.

### 1.4 Progressive discovery

Only **Unreleased** and the **most recent release** are inline. When a new release ships, the previous "latest" section is moved verbatim to `docs/changelog/<version>.md` and a one-line link is added under [§3 Older releases](#3-older-releases). The most recent release stays inline so the common reader and agent path — "what changed lately?" — is one file deep.

## Unreleased

### Added

- [§FS-config.3.9.2](functional-spec/FS-config.md#392-the-homeless-kind): the citing kind of every site outside every configured home is now **nameable**. `code` is its default name, not a fixed one — a Terraform, SQL, or prose tree may declare it and call it what it is (`[[kinds]] kind = "src", citable = false`, no `folder` or `file`, optionally a `title` that becomes its citation-directions scope). Exactly one entry may be it, and `code` is reserved to that entry; a config that names its complement `src` has no `code`, so `[citations.code]` in it is an unknown kind rather than a rule that quietly matches nothing. It still gets no Project map row and still renders last in the citation directions, so no existing repository's managed block moves.
- [§FS-config.3.4.1](functional-spec/FS-config.md#341-citable--kinds-that-declare-no-ids): `[[kinds]] citable = false` — a kind that is a *place* rather than an ID namespace. Its home is scanned and its citations are classified and directed like any other, and it declares nothing: no ID grammar, no `KIND ∈ {…}` entry, no `--kind` or `grund id` selector, no index, and a declaration inside its home is a misplaced declaration ([§FS-check.3.7](functional-spec/FS-check.md#37-misplaced-declaration-configured-kind-home)). Obligations attach per scanned file in the home, `.md` included, and `require_grounding` covers those files too — otherwise `must` on a home that is usually all Markdown would silently never fire ([§FS-check.3.11](functional-spec/FS-check.md#311-missing-required-citation), [§FS-check.3.6](functional-spec/FS-check.md#36-ungrounded-source-file-opt-in)). Findings and the generated block name such a kind by its **place** — `skills/ must cite FS` — never by a name nobody can write. Prefix-freedom is scoped to citable kinds, so `skill` beside a citable `SKI` now loads; names stay unique across the whole table. Decided in [§DF-non-citable-kinds](decisions/functional/DF-non-citable-kinds.md#df-non-citable-kinds-a-kind-may-declare-no-ids-and-stays-one-kinds-table-when-it-does), proposed in [§DISC-id-less-kinds](discussions/proposals/2026-08-25-id-less-kinds.md#disc-id-less-kinds-kinds-that-declare-no-ids). Additive, so `grund_config_version` stays at 1.

- [§FS-check.4.6](functional-spec/FS-check.md#46-declaration-missing-from-its-kinds-index), [§FS-check.3.17](functional-spec/FS-check.md#317-index-entry-is-not-a-link): a folder kind's index must list every declaration in its folder, as a full Markdown link. A missing entry is a warning naming the release it becomes an error in ([§REQ-backwards-compatibility.2](requirements/REQ-backwards-compatibility.md#2-the-deprecation-path)); an entry that is present and unlinked is an error, because `grund fmt --write` fixes it ([§REQ-backwards-compatibility.3](requirements/REQ-backwards-compatibility.md#3-loud-mechanical-migrations)). Decided in [§DF-index-entry-form](decisions/functional/DF-index-entry-form.md#df-index-entry-form-an-index-entry-is-one-full-link-per-id-and-nothing-else-about-the-page) and [§DF-index-compatibility-ramp](decisions/functional/DF-index-compatibility-ramp.md#df-index-compatibility-ramp-a-findings-ramp-follows-its-fix-command-not-the-size-of-the-offence). (PR #134)
- [§FS-check.4.6](functional-spec/FS-check.md#46-declaration-missing-from-its-kinds-index): a canonical bare-ID link in a configured kind index enrolls an external inline source declaration directly, without the otherwise-empty Markdown stub; `show` and `list` keep the source as the only declaration home, and only the exact enrollment site is discounted as navigation ([issue #133](https://github.com/vjovanov/grund/issues/133), PR #135).
- [§FS-config.3.4](functional-spec/FS-config.md#34-kinds--recognized-kinds): `[[kinds]] index` names the index file, relative to `folder`. It defaults to `README.md`, `index = false` opts a kind out, and setting it on a kind with no `folder` is a config error. A named value must be a relative path inside `folder` naming a `.md` file — an absolute or `..` path would read outside the tree the config describes, and the cross-reference pass that repairs an entry runs on Markdown only. Purely additive, so `grund_config_version` stays at 1 ([§FS-config.5](functional-spec/FS-config.md#5-schema-versioning)).

### Changed

- [§FS-config.3.4](functional-spec/FS-config.md#34-kinds--recognized-kinds): `[[kinds]] prefix` is renamed **`kind`** — the word the `{kind}` placeholder, the `--kind` selector and the `[citations.<kind>]` key already use, and the only one that stays true now that a row can name something that never prefixes an ID. `prefix` still loads and earns one warning per config naming the release it stops in ([§REQ-backwards-compatibility.2](requirements/REQ-backwards-compatibility.md#2-the-deprecation-path)); setting both keys on one entry is an error. `grund config show` prints the canonical spelling whichever the file used ([§FS-config.4.2](functional-spec/FS-config.md#42-grund-config-show-path)), so the migration is one `grund config show > grund.toml` away. The removal is [§RM-kind-prefix-removal](roadmap.md#rm-kind-prefix-removal-stop-loading-the-deprecated-kinds-prefix-key).
- [§FS-config.3.5](functional-spec/FS-config.md#35-scan--what-gets-walked): every configured `[[kinds]]` home is walked whether or not `[scan] include` lists it, for every kind; `include` now names the *extra* roots. **Upgrade note:** a repository whose home sat outside `include` had that home's citations *invisible* rather than dangling — no resolution, no finding — and now sees them. They were always true of the tree; the run was not reading it.
- [§FS-config.3.4.4](functional-spec/FS-config.md#344-the-default-kinds): the default `[[kinds]]` table replaces `E2E` with two non-citable kinds — `e2e` (`tests/e2e`, must cite `FS`, should-not cite `AR`) and `integration` (`tests/integration`, should cite `AR`). A test cites the document whose claim it proves and is never cited back. `E2E` remains fully supported and is what this repository declares; only the *default* changed, so a config `grund init` wrote is unaffected. **Upgrade note:** a repository with **no `[[kinds]]` block at all** *and* an `e2e/cases/` corpus loses the case machinery that pruned its fixture trees ([AR-scanner.6](architecture/AR-scanner.md#6-e2e-case-declarations)) and starts scanning them; the fix is one `[[kinds]]` block declaring the `E2E` kind it was relying on by default. Argued in [§DF-non-citable-kinds.3](decisions/functional/DF-non-citable-kinds.md#3-consequences) under the pre-1.0 licence of [§REQ-backwards-compatibility.4](requirements/REQ-backwards-compatibility.md#4-what-was-never-a-promise).
- [§FS-id.1](functional-spec/FS-id.md#1-inputs): `grund id` handed a kind it cannot mint from exits `2` with the `error:` / `known kinds:` pair in every case. A configured non-citable kind used to fall through the generic rejection path and exit `1` with a bare line, which is the shape for a bad *title*, not for a bad kind.
- [§FS-init.2.1](functional-spec/FS-init.md#21-files-written-updated-or-left-in-place): `grund init --docs` scaffolds `tests/e2e/README.md` and `tests/integration/.gitkeep` in place of `e2e/README.md` and `e2e/cases/.gitkeep`, following the two test homes the generated config now names.
- [§FS-check.4.1](functional-spec/FS-check.md#41-unused-declaration), [§FS-list.1](functional-spec/FS-list.md#1-inputs): an index entry no longer counts as an inbound citation for the unused-declaration warning or `grund list --unused`. An index names every declaration in its folder by construction, so counting its entries would empty the signal ([§DF-index-not-an-inbound-citation](decisions/functional/DF-index-not-an-inbound-citation.md#df-index-not-an-inbound-citation-an-index-entry-is-navigation-not-use)).
- [§FS-fmt.6.1](functional-spec/FS-fmt.md#61-scope): `grund fmt` runs the cross-reference pass on a kind's index entries whatever `[fmt.cross_refs] enabled` says, so the fix for an unlinked entry is plain `grund fmt --write` in every configuration. Reached that way the pass wraps the entries and nothing else on the page — a repository that turned generated links off gets the smallest write that clears the error ([§DF-index-always-linkified.2.2](decisions/functional/DF-index-always-linkified.md#22-it-follows-the-passs-own-gate-and-reaches-the-entries-rather-than-the-page)).
- [§FS-config.3.4](functional-spec/FS-config.md#34-kinds--recognized-kinds): the `index` default is keyed on the kind prefix for a declared `[[kinds]]` block exactly as for the built-in list, so `E2E` defaults to `index = false` either way. **Upgrade note:** without this, every `grund.toml` written by `grund init` before this release — which declares `[[kinds]]` and could not have spelled a key that did not exist — would have taken one [§FS-check.4.6](functional-spec/FS-check.md#46-declaration-missing-from-its-kinds-index) warning per e2e case, and lost its `success` line. Measured on this repository: 391 warnings. A project that wants an index for its `E2E` folder writes `index = "README.md"`.
- [§FS-init.2.1](functional-spec/FS-init.md#21-files-written-updated-or-left-in-place): `grund init --docs` scaffolds `docs/decisions/functional/README.md` and `docs/decisions/architectural/README.md` in place of the two `.gitkeep` files, so every folder kind with an index is scaffolded with one.

## 2. [0.11.0] — 2026-08-24

### Fixed

- [§FS-lsp.2.2](functional-spec/FS-lsp.md#22-lifecycle) / [§AR-lsp.2](architecture/AR-lsp.md#2-state): **nested and multi-root editor workspaces no longer silently hide citations outside the first folder** ([issue #126](https://github.com/vjovanov/grund/issues/126)). LSP workspace folders are now config-discovery anchors: a nested IntelliJ project base resolves to its enclosing Grund project and scans the configured include roots, while independent initial folders keep separate snapshots so equal local IDs cannot bleed across projects. The server advertises workspace-folder support and applies later add/remove notifications, rebuilding and republishing diagnostics from the remaining folder set. PR #127

  Multi-root discovery brought a second question with it — which of several projects answers for a document — and one resolution now settles it for every surface. A containing root claims the document, the deepest one where project trees nest; failing that, exactly one project whose scan actually read it claims it. Multiple independent projects that only scan the same external file leave it unowned rather than guessing by root depth. That scan fallback matters because a project's reach is not its root: `[scan] include` is a scan scope rather than a fence ([§FS-config.3.5](functional-spec/FS-config.md#35-scan--what-gets-walked)), so a symlinked include root canonicalizes outside the project directory and an include path may be parent-relative. Deciding ownership on the root prefix alone would have gone silent — no hover, definition, references, links, or shorthand expansion — on files `grund check` reports on, which is the same class of hidden citation as #126. `LspSnapshot` therefore carries `scanned_files`, the set its scan read. Because at most one project owns a document, diagnostics are published by that owner alone: a file two overlapping editor folders both scan — an enclosing workspace and one of its members, say — no longer collects each finding twice, nor the two projects' disagreeing readings of one citation side by side.

  A folder that cannot become a project no longer takes the session with it ([§REQ-never-crashes](requirements/REQ-never-crashes.md#req-never-crashes-garbage-in-diagnostic-out)). A folder URI with a non-`file:` scheme — editors mix virtual and remote folders into one window, and only the first folder used to be read at all — is skipped with a note on stderr instead of aborting `initialize` before the client gets an answer. A folder whose `grund.toml` will not load is skipped the same way: previously one half-typed config failed the whole batch, so at startup no folder got a server, and mid-session the error reached only stderr while every project quietly kept serving its pre-edit snapshot. Each project is now built on its own and keeps its last good snapshot when its own scan fails. In the same pass, an edit re-scans only the projects that can see the edited document, so the per-keystroke cost tracks the edited project rather than the number of open folders; watched-file creates and deletes still rebuild everything, since a path no project has read belongs to none of them.
