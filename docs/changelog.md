# Changelog

Records every notable change to `grund`. Versions follow semver; the **latest release is inline** in this file, and **older releases live one-per-file under `docs/changelog/`** so a reader (human or agent) only loads the history they ask for. Each entry cites the FS/AR/G/DF IDs it touches, so the changelog is itself part of the conformant tree (`grund .` validates the citations).

Schema-version bumps are called out explicitly: `grund_config_version` ([§FS-config.5](functional-spec/FS-config.md#5-schema-versioning)) and the `AGENTS.md` init block version ([§FS-init.2](functional-spec/FS-init.md#2-outputs)). A bump to either is a breaking change for the consumer and must appear under **Changed** with a migration note.

## 1. Conventions

### 1.1 Sections per release

`Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security` — the Keep-a-Changelog set; omit any with no entries. A large entry (the first release, folding in pre-history, is the case in point) may add narrative subsection headings — e.g. `Baseline`, `Renamed`, `Implemented`, `Distribution and bindings` — for readability when the standard six would bury the structure; the semver-relevant changes still live under the standard names.

### 1.2 Schema version callouts

Any change to `grund_config_version` or the `AGENTS.md` block version goes under **Changed** with the prefix `**Schema:**` and a one-line migration pointer.

### 1.3 Entry style

One bullet per change, present tense, leading with the affected ID. Example: `§FS-show: add --head mode for truncated output`.

### 1.4 Progressive discovery

Only **Unreleased** and the **most recent release** are inline. When a new release ships, the previous "latest" section is moved verbatim to `docs/changelog/<version>.md` and a one-line link is added under [§3 Older releases](#3-older-releases). The most recent release stays inline so the common reader and agent path — "what changed lately?" — is one file deep.

PR #25.
- [§FS-lsp](functional-spec/FS-lsp.md#fs-lsp-grund-ships-an-optional-lsp-server): switch the checked-in VSCode/VSCodium setup from `zsol.vscode-glspc` to `wdomitrz.simple-lsp-client`. - [§FS-lsp.2.3](functional-spec/FS-lsp.md#23-editor-configuration-one-time-per-editor): recommend configuring the editor's LSP client in **user (global) settings** rather than a per-repo file, so `grund-lsp` runs in every project instead of only repos that ship an editor config. A repo without the per-repo config silently falls back to the editor's built-in behavior — citations underline a single hyphen-delimited word and find-references misses the citation sites. Documented in the README, the LSP setup guide, and the `grund init` guided-setup skill. PR #25.
- [§FS-init.2](functional-spec/FS-init.md#2-outputs) / [§AR-workspace.3.1](architecture/AR-workspace.md#31-the-rule) / README §4: document the "marker = live citation" rule now that a `§`-marked token is a checked citation inside Markdown backticks too — the generated `AGENTS.md` grounding block gains a **Marker = live citation** rule (same v3 block, re-rendered on the next `grund init`), the README marker guide gains the same note, and the `<§>` illustrative-marker notation used across the specs is finally explained where it first appears. PR #44.

### Fixed

- [§FS-lsp.1](functional-spec/FS-lsp.md#1-capabilities): a malformed or failing LSP message no longer tears down the session — a request that fails returns an error response and a bad notification is logged and skipped, so one bad message cannot drop the editor's connection. The server also reads each file at most once per snapshot when computing token ranges and resolves the edited file's config once per on-type keystroke, instead of once per token / twice per keystroke. PR #25.
- [§FS-lsp.1.2](functional-spec/FS-lsp.md#12-hover-preview): link citations inside hover previews using the displayed citation token, so workspace-local hover prose like `§FS-002-b` becomes clickable even when the LSP query ID is qualified as `root/FS-002-b`. PR #25.
- [§FS-lsp.1.2](functional-spec/FS-lsp.md#12-hover-preview): declaration-side title hovers now return a minimal title body with the whole-title range, giving Codium/VSCode-style clients an explicit hover range for Markdown declaration headings, numbered section headings, and inline-spec stub titles. PR #25.
- [§FS-lsp.1.1](functional-spec/FS-lsp.md#11-diagnostics) / [§FS-lsp.1.2](functional-spec/FS-lsp.md#12-hover-preview): hover on an unresolved citation now returns nothing instead of echoing the diagnostic message, and line-level diagnostics no longer borrow the citation token range. The `publishDiagnostics` entry, with its nearest-ID hint, is the single source of the citation error text, so editors that render diagnostics inside the hover popup stop showing it twice. PR #25.
- [§FS-lsp.1.3](functional-spec/FS-lsp.md#13-go-to-definition) / [§FS-lsp.1.3.2](functional-spec/FS-lsp.md#132-document-links): make Markdown declaration titles navigate as whole-title spans, make inline-spec stub titles link to the source doc-comment declaration, and keep source-comment citation references visible from Markdown navigation. Return go-to-definition results as `LocationLink`s carrying the whole `§<ID>` or title token as their origin span unless a client explicitly sets `textDocument.definition.linkSupport = false`, so editors underline one navigable unit instead of the single word under the cursor. PR #25.
- [§FS-lsp.1.3.3](functional-spec/FS-lsp.md#133-occurrence-highlight): implement `textDocument/documentHighlight` so the whole `§<ID>` citation (or declaration, section, or stub title) under the cursor is marked as one span, plus same-ID occurrences in the file. Editors such as Codium that otherwise fall back to a word pattern were boxing only one sub-word of a citation like `§FS-lsp.1.3`; they now mark the entire reference. PR #25.
- [§FS-lsp.1.3.2](functional-spec/FS-lsp.md#132-document-links): stop emitting a self-pointing document link on ordinary Markdown declaration titles. The self-link covered the same span as go-to-definition and won the editor's Ctrl-click, navigating the title onto its own line instead of showing the declaration's code-reference usages; the title now resolves to go-to-definition (and hover) usages on click. PR #25.
- [§FS-lsp.1.4](functional-spec/FS-lsp.md#14-live-trigger-transform) / [§FS-distribution.4](functional-spec/FS-distribution.md#4-release-process): make LSP on-type formatting use each workspace member's trigger and marker, publish `grund-lsp` in the Cargo release path, and keep the checked-in VSCode setup portable. PR #25.
- [§AR-scanner.2.3](architecture/AR-scanner.md#23-citation-detection): a marker-prefixed **qualified** citation (`<§>alias/ID`) inside a Markdown inline-code span is now recognized, matching the unqualified form, so `grund check`, `grund refs`, and the LSP resolve and navigate cross-namespace citations written in backticks. The inline-code carve-out — a guard against path-like `alias/ID` tokens — previously fired in Markdown too and silently dropped these citations; it now applies only in source files, where `alias/ID` genuinely collides with paths and string literals. PR #44.
